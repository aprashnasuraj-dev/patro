# Panchang–Jyotish source archive extraction and public visibility policy

## Source archive extraction

This is a source inventory and implementation-provenance note. The ZIPs are independent reconstruction/audit inputs; they are not proof of numerical parity with Drik Panchang or official observance accuracy.

### V1 — `drik_independent_panchang_v1.zip`

Extracted 244 files (about 1.24 MB uncompressed). The main contents include:

- Python calculation engine and modules for Panchang events, planetary positions, lunar month handling, observances, timelines, and Kundali.
- A SQLite `panchang.sqlite` database (about 553 KB), locale strings in Nepali and English, and a FastAPI API.
- 210 generated daily JSON fixtures spanning Kathmandu, Delhi, and Tokyo for selected dates in 2026, plus fixture-building and comparison scripts.

The README says it is not Drik's source code and does not claim exact parity. The fixtures are generated by this same engine, so they establish repeatability rather than independent truth. Known gaps include observance precedence and skipped/repeated Tithi rules, regional ritual rules, auspicious-time selection, combustion thresholds, high-latitude and timezone-history behavior, and full Nepali UI coverage. A sample visual comparison found minute-scale differences in sunrise/sunset, which further argues against treating this archive as a certified oracle.

### V2 — `drik_independent_panchang_v2_complete.zip`

Extracted 533 files (about 1.84 MB uncompressed), including V1, with extensions and rulepack contracts for Jyotish, Pancha Pakshi, planetary events, Muhurat, Vedic time, regional dates, quality checks, and database migrations. The V2 feature index reports 67 topics: 14 marked implemented, 29 partial, and 24 not implemented. Its README describes this as an independent reconstruction; several rulepacks are specifications/templates, not production-ready calculations or approved religious rules.

A specific example is `extensions/pancha_pakshi.py`: it returns the bird/activity names but sets `prediction: null` and status `reviewed traditional mappings not supplied`. The matching JSON rulepack is marked partial and identifies the traditional mapping table/reference corpus as a gap. This is not a working Pancha Pakshi predictor, so it must not appear as a usable calculator until the missing mapping is implemented and checked against a reference corpus.

### Deep integration audit — `aafnaipatro_drik_deep_integration_audit_v3.zip`

The audit bundle contains a 91-feature crosswalk, live-route matrix, calculation/runtime map, change plan, test matrix, risk register, DTO/schema notes, and release gates; it also nests the earlier source bundles. Its recommendation is not to run V2 as a parallel live Panchang platform. Instead, use the existing Aafnai Patro archive/data path, existing route owners, JanmaPatro engine and My Time integration, while keeping independently calculated candidates separate from archived or officially published facts.

The audit's production-data statements are snapshot observations, not a fresh re-query of live database contents. Audit plans, reference lists, and test matrices are not themselves implementation or passing test evidence.

## Public feature policy

- Keep all 91 feature IDs and acceptance-ledger rows as the internal inventory/crosswalk. Do not erase them just because an entry is not ready.
- The public hubs show only functional existing destinations and tools with an actual browser-side calculation: 17 existing destinations plus 48 browser-preview tools, **65 visible items total**.
- The 26 reference-only entries are filtered out of public feature cards. This includes Pancha Pakshi, the unsupported Muhurat combinations, the reference-only regional calendar/festival cards, and other entries that currently have no end-to-end working output.
- Kshaya/Vriddhi Tithi (F010) remains visible because there is a real sunrise-to-sunrise pattern checker. Its computed pattern is only an indication, not an official festival/vrata determination.
- Panchak and Ganda Moola (F021/F022) remain available as browser-calculated candidate intervals with their candidate/unverified caveat. They do not claim an official observance verdict.
- The regional workspace keeps links to existing Bikram Sambat, Nepal Sambat, and community-calendar routes. The unsupported regional placeholder cards are removed rather than removing those working calendar routes.

The 91-row acceptance CSV continues to distinguish the full engineering inventory from the smaller public list; blocked rows remain present for future implementation and source review, but are not advertised as working tools.
