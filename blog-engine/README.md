# Mission Mangal — isolated Python editorial pipeline
This standalone subdirectory follows the requested `engine/`, `providers/`, `data/`, `prompts/`, `research/`, `src/`, `public/`, `tests/` structure. Workflows are stored in `blog-engine/.github/workflows/` as templates and **do not execute automatically** inside the host repo; an explicit future reviewed opt-in wiring step is required. The existing root production Cloudflare Worker, Vite/React build, calendar, Facts, route handlers and sitemaps are untouched.

Four URL families are reserved according to intent: `/articles/{slug}/`, `/blogs/{slug}/`, `/facts/{slug}/`, `/what/{slug}/`. Existing Facts routes have priority; before integrating `/facts/` paths, audit collisions against actual deployed routes and reserve any existing paths. Do not overwrite any legacy page. All published content is represented in one isolated `sitemap-missionmangal.xml`, capped at 2,000 rendered approved URLs. No placeholder URLs appear in sitemap.

Every record has stable ID, stage, source/claim/media metadata, author **AafnaiPatro Editor Team**, and a durable append-only ledger in `data/article_ledger.jsonl`. Locking is single-host; distributed workers require a shared transactional job store and claim leases (D1/Queues), rather than simultaneously appending to this file. No secrets, public API calls or automatic publishing in the initial implementation.

Run unit tests: `cd blog-engine && python -m unittest discover -s tests -v`. Node renderer/URL tests: `node --test missionmangal/tests/*.test.mjs`. API catalogs are discovered/registered in `missionmangal/config/catalogs.json`, not executable automatically. Four folders do not imply every source has commercial rights or a free plan. The Astro preview config is optional; this root repo does not migrate frameworks.
