# Master content-routing and job contract

A 2,000-article target is allocated across four **content formats**, selected by genuine reader intent rather than arbitrary quotas: `article` -> `/articles/{slug}/` (deep investigations/analyses); `blog` -> `/blogs/{slug}/` (editorial explainers); `fact` -> `/facts/{slug}/` (evidence-backed fact deep dives); `answer` -> `/what/{slug}/` (direct question answers). All use a persistent article ID and a canonical URL, shared byline **AafnaiPatro Editor Team**, descriptive English body, 5–20 distinct verified *used* sources, author–date inline citations and APA-style bibliography. Images are mandatory; video/audio included where appropriate and cleared. The engine is not authorized to hijack existing `/facts` index or existing API/feature routes; any collision is a hard integration stop.

Ledger events are append-only and idempotent when the same ID/status/payload is retried. Each stage is explicit: discovered -> researching -> sourced -> draft -> editing -> verifying -> verified -> review -> approved -> rendered -> published. Blocked entries can be researched again. A quality score alone cannot set publish_approved. Duplicate detection spans IDs, canonical URLs, topic intent and semantic/editorial review. For distributed execution use D1/Queues transactional leases and idempotency keys; JSONL locking supports a single host only. Keep all provider adapters disabled until reviewed.

The requested `blog-engine/.github/workflows/` structure is included as **inactive templates** because GitHub Actions only recognizes workflows under the host repository's root `.github/workflows/`. The existing PR-only Mission Mangal root workflow runs offline tests, without API secrets, cron, publication or Cloudflare deployment. An optional Astro preview config is not a replacement for the actual Vite/React plus Cloudflare Worker production architecture. The staged sitemap `sitemap-missionmangal.xml` includes only reviewed rendered packages (up to 2,000 URLs across all four folders) and is not publicly accessible until a future separate route/build integration is accepted.
