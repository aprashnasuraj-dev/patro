Bikram Sambat (Nepali) to AD Date Converter

Standalone adapter for the project’s validated Bikram Sambat civil-date dataset, with trust-tier metadata and no fabricated arithmetic approximation.

Integration blocker: The standalone package does not yet contain the existing validated 77,070-day BS↔AD month/day dataset. Reusing that exact local dataset is required; an approximate “+56/57 years” conversion would be misleading.

Result

Use the sample state or enter your values, then run the tool.

What this tool does

The prepared core walks an injected year-by-year month-length table from a known BS↔AD anchor and returns the dataset’s trust tier with the converted date.

How to use it

At integration time, wire the existing validated local dataset into the BsDataset interface. Until then, the UI returns an explicit data-dependency blocker.

Worked example

The integration fixture expects BS 2083-01-01 to map to AD 2026-04-14, but this pair remains deferred until checked against the exact validated dataset being imported.

Supported formats

BS year/month/day fields. Intended dataset coverage from the existing project is BS 1883-01-01 through 2093-12-30, with distinct trust tiers by historical segment.

Assumptions

No arithmetic formula can replace the project’s tabulated month-length mapping. The package must reuse the previously validated local dataset.

Limitations

SOURCE BLOCKED: month-length data is intentionally not reconstructed from memory or a single third-party table in this run.

FAQ

Does normal use transmit my data?

No. The production intent is browser-side processing with no account, worker call or third-party transmission.

How are ambiguous dates or times handled?

The tool exposes the relevant convention, calendar variant, time zone or clamping rule and returns an explicit warning or error when a silent guess would be misleading.
