Mission Mangal · TOOL-0303

Time Zone Meeting Planner Grid

Resolve a wall-clock meeting time in one IANA time zone, expose DST ambiguity, and compare nearby slots across multiple participant zones using browser-local time-zone data.

Result

Use the sample state or enter your values, then run the tool.

What this tool does

It converts one explicitly resolved local wall time into a real instant, then displays a ±4/±8-hour grid in each participant’s IANA time zone.

How to use it

Enter the reference date/time and zone, add participant zones, and choose how DST overlaps should be handled. DST gaps are rejected rather than shifted silently.

Worked example

A 09:00 Kathmandu meeting is resolved to one UTC instant; London, New York and Tokyo cells are formatted from that same instant so DST is reflected by the browser’s time-zone data.

Supported formats

IANA-style zone identifiers such as Asia/Kathmandu, Europe/London and America/New_York. Date/time inputs use Gregorian YYYY-MM-DD and 24-hour HH:MM.

Assumptions

Runtime offsets come from Intl.DateTimeFormat in the user’s browser/OS. IANA 2026e is the current upstream reference, but the embedded browser tzdb version is not directly observable.

Limitations

Political time-zone changes can be announced with little notice. A stale browser can therefore disagree with the latest IANA tzdb. Historical pre-1970 fidelity also varies by platform.

FAQ

Does normal use transmit my data?

No. The production intent is browser-side processing with no account, worker call or third-party transmission.

How are ambiguous dates or times handled?

The tool exposes the relevant convention, calendar variant, time zone or clamping rule and returns an explicit warning or error when a silent guess would be misleading.
