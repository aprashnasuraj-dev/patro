File Encryptor and Decryptor in Browser (AES-GCM)

Encrypt files in bounded 1 MiB authenticated chunks with AES-256-GCM, deriving one file key via PBKDF2 and constructing a unique nonce from a random prefix plus chunk counter.

Result

Use the sample state or enter your values, then run the tool.

What this tool does

It authenticates each 1 MiB chunk independently with AES-GCM. Each chunk nonce is unique within the file: an 8-byte random prefix plus a 32-bit big-endian chunk counter.

How to use it

Choose a file and password, encrypt to .apfenc, then decrypt that container with the same password. The custom header records KDF/cipher/version metadata.

Worked example

A 2.5 MiB input is framed into three authenticated chunks. Tampering with any ciphertext, header, chunk length or ordering causes authentication failure.

Supported formats

APFENC1 binary container; source cap 256 MiB; 1 MiB plaintext chunks; PBKDF2-HMAC-SHA-256; AES-256-GCM.

Assumptions

The 256 MiB cap keeps the current Blob-assembly implementation within a defensible browser-memory envelope. Static app delivery remains local to the site.

Limitations

This custom format is application-specific and should not be presented as a general standard. For very large files, a native tool with streaming output and audited standard container may be preferable.

Privacy and security

File contents and password remain browser-local. The tool does not upload either.
