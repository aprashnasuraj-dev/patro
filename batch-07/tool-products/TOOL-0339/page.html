URL and IP Defanger/Refanger for Security Reports

Reversibly defang or refang one URL/domain/IP indicator for incident reports using visible hxxp(s), [.] and [:] substitutions without making the result clickable.

Result

Use the sample state or enter your values, then run the tool.

What this tool does

It changes only indicator syntax commonly used to reduce accidental activation in security reports. URL path dots are preserved when the input parses as a URL, while host dots are defanged.

How to use it

Paste one indicator and choose Defang or Refang. The result remains inert text in the interface.

Worked example

https://example.com/a.b becomes hxxps://example[.]com/a.b; a plain IPv4 address 192.0.2.10 becomes 192[.]0[.]2[.]10.

Supported formats

Absolute URLs, domains, IPv4/IPv6-like indicators and already-defanged strings using hxxp(s), [.], [:] and [@].

Assumptions

Defanging is a reporting convention, not a security boundary. Reversibility is prioritized over aggressive normalization.

Limitations

Obfuscated indicators can have many forms; this bounded transform does not decode nested percent-encoding, Unicode escapes or arbitrary malware-analysis syntax.

Privacy and security

Indicators stay local; no DNS, HTTP or reputation lookup is performed.
