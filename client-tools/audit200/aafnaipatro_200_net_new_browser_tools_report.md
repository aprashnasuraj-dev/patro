## Technical risk report

|Area|Risk|Required mitigation|
|---|---|---|
|Tax/benefit planners|Versioned annual rules|Hard-code nothing into formulas; separate 2026 config, source dates and disclaimer. Regression-test thresholds.|
|Mortgage/legal-like timelines|Model uncertainty|Use user-entered lender/state terms where rules differ; do not present eligibility as legal advice.|
|Archive inspectors|Zip bombs / memory pressure|Inspect central directory first; cap decompression ratio, expanded bytes and entry count; stream where possible.|
|DuckDB/Parquet|Large WASM payload + RAM|Lazy-load WASM; run in Worker; warn before loading multi-GB files.|
|GIS files|Malformed geometry / large datasets|Worker parsing, feature caps, repair preview rather than silent mutation.|
|Media parsers|Codec/browser variance|Prefer metadata parsing over transcoding; feature-detect WebCodecs and provide clear unsupported states.|
|ICC/color tools|Color-management differences|Report profile metadata precisely; do not promise identical rendering across browsers/OSes.|
|Optimization tools|NP-hard packing|Use bounded heuristics, deterministic seed and an explicit 'not guaranteed globally optimal' limitation.|
|Network/security parsers|Security-sensitive pasted configs|Never execute pasted content; parse text only; redact secrets in exports by default.|
|AI/LLM planners|Rapid model/runtime change|User-supplied architecture fields must override presets; timestamp presets and state that estimates are not benchmarks.|
|Solar/electrical planning|Safety-critical use|Use manufacturer/user data and standards references; label as planning aid, not wiring/design approval.|
|Travel/residency|Rules can change and exceptions exist|Version rule tables; show day arithmetic; avoid definitive legal/immigration conclusions.|
