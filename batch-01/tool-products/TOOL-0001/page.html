    A reproducible example

    For id,name,active followed by 001,Asha,true and 002,Ravi,false, the default result includes:

    type Record {
  id: ID
  name: String
  active: Boolean
}

type Query {
  rows: [Record!]!
}

    The identifier header keeps 001 as an ID. Boolean inference accepts only lowercase true and false. Fields stay nullable unless you explicitly enable the non-null option.

    What inference can—and cannot—tell you

    GraphQL Int is limited to −2,147,483,648 through 2,147,483,647. Larger safe integers may become Float; unsafe integers and non-finite numeric values stay String. Ordinary decimal Float values use binary floating point and may round: use String for exact money or decimal identifiers.

    Mixed types, significant leading zeros and whitespace-bearing values stay String. An id or _id/-id/ id suffix suggests ID; this is a heuristic, not a uniqueness check. Blank cells do not supply type evidence. Empty lines are skipped; rows with unequal cell counts are rejected.

    Counterexample: a sample with only integer ages does not prove that future records cannot be null or contain text. Non-null inference is a statement about the supplied sample, not a guarantee.

    Names, dates and privacy

    Invalid field-name characters become underscores; digit-leading names receive field_; reserved double-underscore prefixes are avoided. Collisions get deterministic numeric suffixes. Map these names in your resolvers.

    DateTime is opt-in and custom. This tool recognizes valid Gregorian dates with YYYY-MM-DDTHH:mm:ss[.SSS]Z, years 0001–9999 and up to three fractional digits. Offset timestamps and leap seconds remain String. Supply your own scalar implementation.

    Input stays in page memory and a dedicated worker. No accounts, remote parsing, analytics or storage are used. Cancel terminates processing; Clear removes visible input and results. This is not a secure-erasure guarantee for browser memory.
