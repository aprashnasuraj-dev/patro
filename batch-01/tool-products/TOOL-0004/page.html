Data model migration

Convert plain CREATE TABLE SQL into Prisma models

Conservative conversion deliberately rejects unsupported SQL constructs rather than producing subtly broken relations.

Designed for

Strict SQL subset · Prisma ORM v7 · manual relation review

The local browser workspace will load when this route is activated. You can read the instructions below without JavaScript.

How to use this tool

Paste simple PostgreSQL CREATE TABLE statements, review any conversion limitations and copy the draft into a Prisma v7 schema project.

Worked example

Try this representative input to inspect the output and its warnings:

CREATE TABLE users (
  id INTEGER PRIMARY KEY,
  email VARCHAR(255) NOT NULL UNIQUE,
  created_at TIMESTAMP NOT NULL
);
CREATE TABLE sessions (
  id INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL,
  expires_at TIMESTAMP
);

Supported formats and constraints

PostgreSQL CREATE TABLE subset; Prisma ORM v7 fields

DDL grammars differ across vendors. This deliberately excludes foreign keys, advanced defaults, CHECK constraints and full relation reconstruction. For actual databases prefer Prisma introspection.

Privacy and safety

Source is prepared for local browser execution. There is no automatic upload or third-party conversion API; verify actual behavior during the post-import testing stage. Review any exported content before sharing or executing it.
